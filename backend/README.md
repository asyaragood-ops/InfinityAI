# infinityAI — бэкенд-роутер на C

Принимает сообщения чата от фронтенда и отправляет их **по каскаду моделей**: сначала ИИ №1 (например, бесплатный Gemini 2.5 Flash), а если у него исчерпан лимит (HTTP 429, quota exceeded) или он недоступен — автоматически ИИ №2, №3… Фронтенду возвращается не только текст, но и **кто ответил** (бэйдж «Ответил: Gemini») и история попыток.

## Как работает каскад

```
POST /api/chat ──► модели config.json + catalog.json, упорядоченные стратегией из «Настроек»:
                     1. выключена / нет ключа             → пропуск
                     2. на паузе после 429 или исчерпан
                        локальный лимит (rpm/rpd в SQLite) → «Основной лимит исчерпан. Переключаюсь на резервный ИИ...»
                     3. «try»: запрос к провайдеру
                        ├─ 200            → ответ + метаданные, стоп
                        └─ «catch»: ошибка классифицируется:
                             429 / quota / 402      → лимит: лог + пауза + следующий ИИ
                             401 / 403 / неверный ключ → пауза 10 мин + следующий ИИ
                             5xx, 529, сеть, таймаут → короткая пауза + следующий ИИ
                             400 / пустой ответ      → следующий ИИ без паузы
```

В C нет `try/catch`, поэтому каждый вызов провайдера возвращает `call_result` с полем `kind` (`ok`, `rate_limit`, `quota`, `auth`, `server_error`, `network`…) — это «пойманное исключение» в явном виде. Логика — в `src/router.c`, классификация ошибок — в `src/providers/provider.c`.

**Сколько ждать после 429.** Пауза берётся из ответа провайдера (`Retry-After` или `retryDelay` у Google). Суточный лимит (`PerDay`) — пауза до конца суток UTC; закончились деньги на платном аккаунте (`insufficient_quota`, 402) — 1 час; иначе 60 секунд. Google пишет «exceeded your current quota» даже на минутном лимите, поэтому одно это сообщение не выключает модель на сутки.

## Модели каталога — в каскад автоматически

Рядом с `config.json` лежит `catalog.json` — 117 бесплатных чат-моделей из каталога сайта (Groq, Cerebras, OpenRouter, Mistral, Cohere, NVIDIA NIM, GitHub Models, Cloudflare, SambaNova, Scaleway…), с теми же `id`, что и карточки на странице «Модели». **Как только в «Настройках» введён ключ провайдера, все его модели сразу попадают в каскад** — без перезапуска и правки конфигов. Без ключа они в каскаде не участвуют и в `/api/models` не показываются. Модели из `config.json` главнее: при совпадении `id` запись каталога пропускается.

Для Cloudflare Workers AI ключ вводится как `ACCOUNT_ID:API_TOKEN` (ID аккаунта нужен в адресе API).

Каталог генерируется из того же источника, что и фронтенд: `cd ../frontend && python3 scripts/gen_catalog.py --backend-json > ../backend/catalog.json`. API-имена моделей у провайдеров иногда меняются — если провайдер ответит 404 «модель не найдена», модель ставится на паузу на 6 часов и каскад идёт дальше.

## Настройки роутера (страница «Настройки» сайта)

Сохраняются на сервере (`data/infinity.db`) и применяются к каждому запросу:

| Настройка | Что делает бэкенд |
|---|---|
| Автопереключение при лимите | выкл — пробуется только первая подходящая модель; при её лимите возвращается ошибка, резервные не вызываются |
| Порог переключения (50–100%) | при локальных лимитах (`rpd`, `tpd`, `rpmo`) модель пропускается заранее, когда израсходовано столько % (`rpm` — всегда 100%) |
| Стратегия «Дешевле» | бесплатные модели по порядку каскада, платные — в конце |
| Стратегия «Свободнее» | бесплатные модели, начиная с самой незагруженной (по доле израсходованного лимита), платные — в конце |
| Стратегия «Качественнее» | по `priority` (1 — сильнейшие), платные модели не откладываются |
| Сохранять контекст | выкл — резервной модели после переключения отдаётся только последнее сообщение |
| Уведомлять о переключении | плашка в чате (выполняет сайт) |
| Шифровать ключи | см. «Безопасность» |
| Вкл/выкл модели на странице «Модели» | выключенные модели каскад обходит, закрепить их в чате тоже нельзя |

Модели, подходящие под специализацию запроса (`skill`), всегда идут раньше остальных; закреплённая в чате модель — первой.

**Локальный учёт лимитов.** Если в конфиге у модели указаны `limits` (`rpm`, `rpd`, `rpmo`, `tpd`), роутер считает запросы и токены в SQLite (`data/infinity.db`) и переключается **заранее**, не дожидаясь 429.

## Структура

```
backend/
  CMakeLists.txt
  config.json            порядок каскада и лимиты (без секретов)
  .env.example           шаблон для API-ключей → скопируйте в .env
  src/
    main.c               запуск, загрузка .env и конфига
    server.c             HTTP-сервер: /api/chat, /api/models, /api/health
    router.c             каскад: порядок, try/catch-логика, паузы, метаданные ответа
    quota.c              SQLite: счётчики rpm/rpd/месяц, паузы, журнал попыток
    config.c             config.json и .env
    http_client.c        HTTPS-запросы (libcurl)
    json.c, strbuf.c     разбор и запись JSON
    settings.c           настройки роутера со страницы «Настройки» (хранятся в SQLite)
    crypto.c             шифрование ключей AES-256-GCM, мастер-ключ (Windows: DPAPI)
    platform.c           Windows/Linux: сокеты, время, каталоги
    providers/
      gemini.c           Google AI Studio (generateContent)
      openai.c           OpenAI и все совместимые: Groq, OpenRouter, Mistral, Cerebras, NVIDIA, GitHub Models…
      anthropic.c        Claude (Messages API)
      mock.c             тестовый провайдер без сети
  catalog.json           модели каталога: в каскаде, когда для провайдера введён ключ
  tests/
    test_main.c          130 проверок ядра (без сети)
    integration_test.sh  по настоящему HTTP: Gemini → 429 → GPT-4o, модель каталога по ключу, настройки, шифрование
    mock_providers.py    имитатор API провайдеров для интеграционного теста
```

## Сборка на Windows (MSYS2)

1. Установите [MSYS2](https://www.msys2.org/) и откройте терминал **MSYS2 UCRT64**.
2. Поставьте компилятор и библиотеки:
   ```bash
   pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja \
                      mingw-w64-ucrt-x86_64-curl mingw-w64-ucrt-x86_64-sqlite3 mingw-w64-ucrt-x86_64-openssl
   ```
3. Соберите:
   ```bash
   cd /c/Users/Administrator/Desktop/infinityAI/backend
   cmake -S . -B build -G Ninja
   cmake --build build
   ```
4. Запуск тестов: `ctest --test-dir build --output-on-failure`

Запускать `infinity-router.exe` удобнее из того же терминала UCRT64 — там есть нужные DLL (libcurl, sqlite). Чтобы запускать из обычного окна, скопируйте DLL рядом с exe: `ldd build/infinity-router.exe | grep ucrt64` покажет список.

## Сборка на Linux / macOS

```bash
# Ubuntu/Debian: sudo apt install build-essential cmake libcurl4-openssl-dev libsqlite3-dev libssl-dev
# macOS:         brew install cmake curl sqlite
cmake -S . -B build && cmake --build build
ctest --test-dir build --output-on-failure
bash tests/integration_test.sh build/infinity-router   # нужен python3 и curl
```

## Настройка и запуск

1. Запуск: `./build/infinity-router` (по умолчанию `http://127.0.0.1:8080`).
2. Фронтенд: `cd ../frontend && npm start` — dev-сервер Angular уже проксирует `/api` на порт 8080.
3. **Ключи — на сайте: Настройки → API-ключи.** При сохранении ключ сразу уходит на бэкенд, хранится в `data/infinity.db` и используется каскадом. Ключи, которые были введены в браузере, пока бэкенд не работал, отправляются автоматически при его запуске. Где взять:
   - Google AI Studio — https://aistudio.google.com/apikey (бесплатно)
   - Groq — https://console.groq.com/keys (бесплатно)
   - OpenAI, Anthropic — платные pay-as-you-go
4. Порядок каскада — в `config.json` (сверху вниз). Модель без ключа просто пропускается, так что можно начать с одного Gemini.

`.env` — **необязательный** запасной вариант (например, для сервера без браузера): ключ оттуда используется, только если для провайдера ключ не задан в «Настройках». Связь модели с ключом — поле `key_name`: оно должно совпадать с названием провайдера в «Настройках» (`Google AI Studio`, `Groq`, `OpenAI`, `Anthropic`…).

Пример лога, когда у Gemini кончился бесплатный лимит:

```
WARN  [router] [1a15...] Gemini: Основной лимит исчерпан (HTTP 429: You exceeded your current quota...). Переключаюсь на резервный ИИ...
INFO  [router] [1a15...] Gemini на паузе 41 с
INFO  [router] [1a15...] → GPT-4o (openai/gpt-4o)
INFO  [router] [1a15...] ✓ Ответил: GPT-4o за 812 мс (11+9 токенов) — после переключения
```

### Поля модели в config.json

| Поле | Описание |
|---|---|
| `id` | уникальный id; если совпадает с id карточки во фронтенде (`cat-…`), карточка обновит счётчик |
| `label` | имя для бэйджа «Ответил: …» |
| `provider` | `gemini`, `openai` (любой OpenAI-совместимый API), `anthropic`, `mock` |
| `model` | имя модели у провайдера |
| `base_url` | для OpenAI-совместимых: `https://api.groq.com/openai/v1`, `https://openrouter.ai/api/v1`, `https://api.mistral.ai/v1`… |
| `key_name` | под каким провайдером ключ хранится в «Настройках» сайта; по умолчанию определяется по `provider`/`base_url` |
| `api_key_env` | необязательно: переменная из `.env`, если ключ не задан в «Настройках» |
| `tier` | `free` / `paid` — только для отображения |
| `skills` | специализации (`text`, `code`, `marketing`…); модели с навыком чата идут в каскаде раньше |
| `limits` | локальные лимиты: `rpm`, `rpd`, `rpmo`, `tpd` (0 или нет — без ограничения) |
| `max_tokens`, `max_tokens_field` | длина ответа; для новых моделей OpenAI `max_tokens_field: "max_completion_tokens"` |
| `priority` | 1 — сильнейшие, 2 — средние, 3 — лёгкие; учитывается стратегией «Качественнее» |
| `enabled` | `false` — временно исключить из каскада |

## API

**POST /api/chat**

```json
{ "messages": [{ "role": "user", "content": "Привет" }], "model": "auto", "skill": "marketing" }
```

`model` — `"auto"` (каскад по порядку) или `id` модели, которую закрепили в чате: она пробуется первой, а при лимите каскад продолжается.

Ответ `200`:

```json
{
  "ok": true, "request_id": "1a1524…",
  "text": "…", "badge": "Ответил: GPT-4o",
  "model": { "id": "openai-gpt-4o", "label": "GPT-4o", "provider": "openai", "model": "gpt-4o", "tier": "paid" },
  "switched": true,
  "usage": { "input_tokens": 11, "output_tokens": 9 },
  "attempts": [
    { "model": { "id": "…gemini…", "label": "Gemini", … }, "status": "quota", "limit": true, "http_status": 429, "latency_ms": 180, "message": "HTTP 429: You exceeded your current quota…" },
    { "model": { "id": "openai-gpt-4o", "label": "GPT-4o", … }, "status": "ok", "limit": false, "http_status": 200, "latency_ms": 812, "message": "" }
  ],
  "latency_ms": 1001
}
```

Если не ответил никто — `503` с `"ok": false`, `"error"` и тем же списком `attempts`.

**GET /api/models** — каскад с состоянием: есть ли ключ, счётчики за минуту/сутки/месяц, пауза и её причина.
**POST /api/models/{id}/reset** — снять паузу и обнулить счётчики модели.
**GET /api/health** — проверка, что сервер жив.

**Настройки** (как и ключи — только с этого компьютера и со своего сайта):
- `GET /api/settings` → `{"ok":true,"encryption_available":true,"settings":{"autoSwitch":true,"threshold":90,"strategy":"free","keepContext":true,"notifySwitch":true,"encryptKeys":false,"disabled":[]}}`
- `POST /api/settings` — частичное обновление, например `{"strategy":"quality","threshold":80}`. Неверные значения → `400`.

**Ключи** (только с этого компьютера и только от своего фронтенда — проверяется адрес клиента и заголовок `Origin`):
- `GET /api/keys` — провайдеры каскада и сохранённые: `{"provider":"Groq","set":true,"source":"settings"|"env","hint":"…a1B2","models":["Llama 3.3 70B"]}`. Сам ключ сервер никогда не возвращает.
- `POST /api/keys` `{"provider":"Groq","key":"gsk_…"}` — сохранить; пустой `key` удаляет. После смены ключа пауза моделей этого провайдера снимается.
- `POST /api/keys/bulk` `{"keys":{"Groq":"…","OpenAI":"…"}}` — так сайт досылает ключи из браузера при запуске бэкенда.

## Безопасность

- Ключи хранятся на сервере в `data/infinity.db` (и копией в браузере, чтобы досылать их после перезапуска бэкенда).
- **Шифрование ключей** (переключатель в «Настройках»): ключи в базе хранятся как `enc:v1:…` — AES-256-GCM со случайным nonce и проверкой целостности. Мастер-ключ создаётся при первом запуске в `data/master.key`; в Windows он защищён DPAPI (расшифровать его может только ваша учётная запись Windows на этом компьютере), в Linux/macOS — права `0600`. При включении уже сохранённые ключи перешифровываются, при выключении — возвращаются в открытый вид. Не теряйте `master.key`: без него зашифрованные ключи придётся ввести заново. Копия ключей в браузере (localStorage) не шифруется — это защита файла базы, а не браузера. Сервер не отдаёт ключи обратно — только последние 4 символа. `.env` и `data/` в `.gitignore`.
- Менять ключи и отправлять сообщения можно только со своего сайта: запросы с чужим `Origin` отклоняются (иначе любой открытый в браузере сайт мог бы обратиться к `127.0.0.1:8080`). Ключ с пробелами или переводами строк не принимается.
- По умолчанию сервер слушает только `127.0.0.1`. Перед выкладкой в интернет поставьте его за reverse-proxy с HTTPS и авторизацией: сейчас любой, кто достучится до `/api/chat`, тратит ваши лимиты.
